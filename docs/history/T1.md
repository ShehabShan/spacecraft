## Architecture
- **Option B (Q1):** a new play page under `game/src/play/` with its own minimal Moon boot. It reuses
  core, render and workers unchanged and imports nothing from the M1F harness, because the harness
  patches THREE prototypes at module scope and boots its world as module singletons (page rule,
  AGENT_BRIEF §3). Only the boot constants, the spawn search and the quadtree LOD were reimplemented.
- **Frame order** (`frame/playFrame.ts`, one fixed order per R3F `onFrame`):
  1. input;
  2. `PlayerController`, which writes the KCC input;
  3. `kcc.update` + `core.advance` (real time, 1/60 fixed steps);
  4. render extraction (spin group, floating origin, character root);
  5. `CharacterAnimator.update(telemetry)`;
  6. `ThirdPersonCamera`, then `setDriverPose`;
  7. layer assignment;
  8. LOD + `pool.pump`.
- Camera-relative movement needs no core change: the controller maps the stick into the KCC frame
  (`moveF`/`moveR`), and the KCC's `autoTurnEnabled` turns the body toward its velocity.
- The character is an articulated `AstronautRig` driven by a `ProceduralAnimator` behind the
  `CharacterAnimator` interface, so a GLB animator can replace it later.

## Rulings (Lead, 2026-10-20; APPROVAL LEDGER)
Q2, Q5 and Q8 were delegated to the bot, which recorded its choice and reason.
| Q | Ruling |
|---|---|
| Q1 | Option B (new play page, no harness extraction) |
| Q2 | opt-in KCC `coyoteTime`, default 0, play 0.10 s (delegated: a velocity teleport would bypass the F18 spin-phase launch compose) |
| Q3 | `airControl` 0.3, default 0 |
| Q4 | simple crouch blend pose |
| Q5 | core untouched; jump buffer in the play layer (delegated) |
| Q6 | Playwright smoke in scope |
| Q7 | the `play` page only |
| Q8 | play `MOON_ASTRONAUT.spinOmega` = 0 (delegated: at 0.0005 rad/s the spawn goes dark 21 min after load for ~105 min; 0 keeps Earth fixed in the sky, as on the tidally locked Moon). Harness and KCC defaults unchanged |

**ADR-027** (`docs/decisions/ADR-027-b11-coyote-air-control.md`): Q2/Q3 as optional `AstronautConfig`
fields read as `cfg.coyoteTime ?? 0` / `cfg.airControl ?? 0`, so every existing config compiles and
behaves unchanged. The default path is proven bit-identical by `tools/test-kcc-default-trace.mjs`
(hashes pinned from 9c4ee90); every later KCC edit must keep it green.
