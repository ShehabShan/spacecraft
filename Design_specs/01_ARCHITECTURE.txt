# 01_ARCHITECTURE


## 1. System Boundaries & Update Order
The game loop runs in a strict sequence to ensure 64-bit mathematical purity before any 32-bit physics or rendering occurs.


**The Canonical Tick Order (Fixed 1/60s dt):**
1.  **Macro Update (Float64):** Evaluate planet, moon, and portal rails based on `simTime`.
2.  **Bubble Refresh:** Check if the player has crossed a 256m lattice boundary. If yes, compute origin shift .
3.  **Parented State Compose (Float64):** Evaluate the astronaut's planet-local coordinates and compose them with the planet's rotation rail to find absolute absolute 3D position.
4.  **Rebase (Float32 conditional):** If rebasing, translate all Rapier bodies and procedural chunk origins by exactly  without waking sleeping bodies.
5.  **Forces (Float32):** Apply gravity (evaluated from the Float64 core), thrust, and the aerodynamic drag governor.
6.  **Physics Step (Float32):** `world.step(dt)`.
7.  **Write-back (Float64):** Accumulate the exact  delta changes back to the  core absolute positions. 
8.  **Render Extract:** Extract camera position and render node transforms for Three.js.


## 2. Terrain Generation & Web Worker Memory Pipeline
Terrain generation must never cause V8 Garbage Collection (GC) stutters. 
*   **The Spherified Cube:** Grid vertices are generated using exact spherified cube math (not `normalize()`). 
*   **Seamless Normals:** Edge normals are evaluated analytically from the noise field via central differences using a frame invariant to the vertex direction . **Workers do not communicate with each other.**
*   **LOD Cracks:** Handled by dropping "skirts" radially toward the core. Skirt depth is a conservative constant based on the max error of the LOD level below it.
*   **The Buffer Swap Protocol:**
    1. Worker fills a pre-allocated Float32Array and sends it via `Transferable`.
    2. Main Thread receives it, pulls a `BufferAttribute` from the warm pool, and swaps the array reference.
    3. Main Thread sends the displaced (old) ArrayBuffer back to the Worker pool.
    4. At no point is `new Float32Array()` or `geometry.dispose()` called during gameplay.


## 3. High-Speed Flight & The Aerodynamic Governor
Rapier meshes are generated asynchronously and will be outrun by a ship flying at 2,000 m/s. 
*   **Kinematic Flight:** Above 30 m/s, the ship is a Kinematic body in the Float64 core. It resolves collisions analytically using 2D DDA exact sweeps against the terrain height lattice. Rapier CCD is bypassed.
*   **The Governor:** Ship speed is restricted by . As the ship enters an atmosphere, it is mathematically forced to decelerate via an exact exponential drag map. By the time it reaches terrain, speed is strictly , ensuring Web Workers have had ample time (seconds) to construct the physics colliders.


## 4. The Astronaut Controller (Spherical Walk Math)
*   **Kinematic, not Dynamic:** The astronaut is a Kinematic Character Controller (KCC).
*   **Quaternion Parallel Transport:** Orientation is maintained via Gram-Schmidt reprojection and converted directly to Quaternions. Euler angles (`yaw/pitch`) are strictly prohibited to prevent Gimbal lock and pole-snapping.
*   **The Coriolis Handoff:** The planet's rotational speed (e.g., 52 m/s at the equator) is applied as an analytical transport velocity in the 64-bit core. Rapier only simulates the relative walking displacement, ensuring the astronaut never "skates" across the terrain.


## 5. Dormancy States & Sky Impostors
Every celestial body cycles through four states based on distance:
1.  **Dormant:** Rotation and orbit tracked in formulas only. Not rendered.
2.  **Sky Impostor (Far/Mid Camera):** A procedurally generated 2D quad rendered using the virtual radius formula `R_v = max(R, d * sin(\theta_{art}))`. The fragment shader uses a ray-cone intersection to ensure the pixel silhouette perfectly matches the 3D mesh.
3.  **Awake 3D (Mid/Near Camera):** The 3D quadtree mesh renders. Procedural chunks load based on camera frustum and LOD split distances.
4.  **Active (Physics Bubble):** Chunks within 2 km of the player have Rapier heightfield colliders attached to them. 


## 6. Pause-and-Prime Hydration Pipeline
When a save file is loaded, the game must prevent the ship from falling through ungenerated terrain.
1.  **Freeze:** Set phase to `HYDRATING`. `simTime` is restored but halted.
2.  **Predict:** The 64-bit core calculates the 3D velocity corridor of the ship.
3.  **Generate:** A priority queue forces Web Workers to generate the terrain cells immediately below and ahead of the ship.
4.  **Verify (The Gate):** Physics is only unpaused when Rapier confirms `intersectionsWithShape == EMPTY` at the exact spawn point, proving the terrain has loaded and the ship is safe.
5.  **Run:** A 300ms cosmetic fade occurs while the 60Hz loop begins.
